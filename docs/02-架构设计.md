### 1.1 设计原则

1. **本地优先**：所有操作先写本地 SQLite，UI 不等网络；同步是后台最终一致的复制。
2. **核心库与 UI 解耦**：Iced 与 Slint 只做渲染与输入，业务状态机在 `reedshell-ui`，保证两端行为一致。
3. **服务端零知识**：服务端不实现任何解密逻辑，不引入"服务端加密"后门。
4. **单一密文格式**：本地库与云端存同一份密文，减少"本地明文、云端密文"的两套代码路径。
5. **可替换**：终端解析器、SSH 后端、渲染器、存储层均通过 trait 隔离，便于后续替换或移植。

## 2. 技术选型

| 层 | 选型 | 版本基线 | 理由 / 备注 |
|---|---|---|---|
| 桌面 UI | `iced` | 0.14.x | 纯 Rust、wgpu 渲染、跨 Win/macOS；Elm 架构便于维护 |
| 桌面主题 | `iced-fluent-theme` | 0.1.x | Fluent 2 风格；**新库、v0.1，需 3 天 spike 验证 API 稳定性**，仅允许 `apps/desktop` 直接依赖 |
| 移动 UI | `slint` + `slint-build` | 1.18.x | 原生移动支持、内存占用可控、无 WebView |
| SSH | `russh` | 0.65.x | 纯 Rust、异步、支持 client/server、通道与转发；便于交叉编译到 Android/iOS |
| SFTP | `russh-sftp` | 3.0.x | 与 russh 通道集成 |
| 本地 Shell | `portable-pty` | 0.9.x | ConPTY（Win）/ PTY（Unix）；移动端不启用 |
| 终端解析 | `alacritty_terminal` | 0.26.x | VT 覆盖度高；通过 trait 包裹，保留替换为 `vt100` 的余地 |
| 字体/排版 | `cosmic-text` + `swash` | 最新兼容版 | 字体回退（CJK）、整形、字形栅格化 |
| 客户端存储 | `rusqlite` (`bundled`) | 0.3x | 交叉编译简单，SQLite 全平台；迁移用 `refinery` 或自研版本表 |
| 服务端框架 | `axum` | 0.8.x | Tokio 生态、tower 中间件 |
| 服务端 DB | `sqlx` (MySQL) | 0.9.x | 编译期 SQL 校验、连接池、迁移 |
| 缓存/限流 | `redis` crate | 最新兼容版 | 令牌桶、登录失败计数、SSE 通知（可选） |
| 密码学 | `argon2`、`chacha20poly1305`、`hkdf`、`ed25519-dalek`、`zeroize`、`getrandom` | 最新兼容版 | RustCrypto 系 |
| Web | React 19 + TypeScript + Vite + Tailwind 4 + shadcn/ui | 最新稳定 | TanStack Query、React Router、react-hook-form + zod |
| Web 加密 | `hash-wasm`（Argon2id） | 最新 | 浏览器端派生 `auth_key`，密码不上传 |
| 部署 | Docker Compose + Caddy | — | MySQL 8.4、Redis 7、自动 HTTPS |

> 版本升级策略：桌面端锁定 `iced` 与 `iced-fluent-theme` 的小版本；升级需跑视觉回归与交互冒烟测试。

```
├─ apps/
│  ├─ desktop/                 # Iced 应用（Win/macOS，可编译 Linux）
│  └─ mobile/                  # Slint 应用（Android/iOS）
├─ web/                        # React 管理端
├─ deploy/
│  ├─ docker-compose.yml
│  ├─ Caddyfile
│  └─ migrations/
├─ scripts/                    # 打包、签名、发布脚本
└─ .github/workflows/
```

依赖方向（只允许向下）：

```
apps/*  →  reedshell-ui  →  {ssh, sftp, term, sync}  →  {store, crypto, core}
                                ↘ secrets
reedshell-server → {core, crypto}   # 不依赖客户端库
```

`reedshell-server` 与客户端共享 `core` 中的枚举/常量，但**不共享** `store`（服务端用 sqlx/MySQL）。

## 4. 客户端分层

### 4.1 UI 状态机（`reedshell-ui`）

两端共用的事件驱动模型：

```rust
// 输入
pub enum UiCommand {
    Connect { conn: ConnectionId, split: Option<SplitTarget> },
    Disconnect { tab: TabId },
    CloseTab { tab: TabId },
    Write { tab: TabId, bytes: Bytes },
    Resize { tab: TabId, cols: u16, rows: u16 },
    OpenSftp { conn: ConnectionId },
    StartForward { rule: ForwardId, conn: ConnectionId },
    // ...
}

// 输出
pub enum UiEvent {
    TabOpened { tab: TabId, title: String },
    TerminalOutput { tab: TabId, delta: RenderDelta },
    StatusChanged { tab: TabId, status: SessionStatus },
    SftpProgress { id: TransferId, done: u64, total: u64 },
    SyncState { state: SyncState },
    Toast { level: Level, message: Localized },
    // ...
}

pub struct CoreHandle { cmd_tx: Sender<UiCommand>, evt_rx: Receiver<UiEvent> }
```

- UI 只持有 `ViewModel`（可序列化的纯数据），不直接持有 SSH 会话。
- 所有异步任务在 Tokio 运行时中运行，事件通过 `tokio::sync::mpsc` 回到 UI。
- Desktop：`iced::Subscription` 桥接 `evt_rx`；Mobile：`slint::Timer`/后台线程 + `invoke_from_event_loop`。

### 4.2 终端管线（`reedshell-term`）

```
SSH channel bytes ─► Parser(alacritty_terminal) ─► Grid/Term state
                                                     │
                          ┌──────────────────────────┴──────────────────────┐
                          ▼                                                 ▼
                 RenderDelta (damage)                              Search/Selection/Scrollback
                          │
           ┌──────────────┴───────────────┐
           ▼                              ▼
   Desktop: GPU 实例化字形             Mobile: CPU 合成 RGBA
   (iced shader widget)               (SharedPixelBuffer)
```

- 共享：字体加载、字体回退链、字形图集（`cosmic-text` 整形 + `swash` 栅格化）。
- 桌面：wgpu 管线，每帧仅上传变化单元格的实例数据，目标 60fps。
- 移动：按 damage 区域合成，最多 30fps，只在新输出时刷新。
- **Spike 项**：Iced 0.14 自定义 shader widget 的 API 与 wgpu 版本对齐；若受阻，降级为 CPU 渲染 + `image` 句柄缓存，仍可满足 80×50 视口。

### 4.3 SSH 层（`reedshell-ssh`）

```rust
pub trait Transport {                     // 便于测试注入
    async fn connect(&mut self, target: &Target, hops: &[Hop]) -> Result<SessionHandle>;
}

pub struct SessionHandle {
    pub channel: Channel,                 // shell / exec
    pub sftp: SftpHandle,                 // 独立通道
    pub forwards: ForwardRegistry,
}
```

- 认证链：`publickey(agent) → publickey(keyfile) → password → keyboard-interactive`，顺序可配置。
- 跳板：逐跳建立 `direct-tcpip` 通道，最后一跳在其上开 SSH 会话；每跳独立认证上下文。
- 转发：`direct-tcpip`（本地）、`tcpip-forward`（远程）、本地 SOCKS5 监听器（动态）。
- KeepAlive：默认 30s，3 次无响应判定断线；重连由 `reedshell-ui` 调度（指数退避 1s→30s）。
- 主机密钥：连接前查询本地 `known_hosts`，不匹配则挂起并抛 `HostKeyMismatch`，由 UI 决策。

### 4.4 存储层（`reedshell-store`）

- 单文件 `local.db`（SQLite），WAL 模式，`secure_delete=ON`。
- 所有敏感字段（连接、密钥、偏好）以密文列存储；解密仅在内存中按需进行。
- 写入路径：`Repo::upsert()` → 本地事务 → 标记 `dirty` → 触发同步（若已登录）。
- 迁移：`schema_version` 表 + 顺序迁移脚本，升级前自动备份（保留最近 3 份）。
- 并发：单写线程（`Mutex<Connection>`）+ 读连接池；所有调用经 `spawn_blocking`。

### 4.5 系统安全存储（`reedshell-secrets`）

```rust
pub trait SecretStore: Send + Sync {
    fn get(&self, key: &str) -> Result<Option<SecretBytes>>;
    fn set(&self, key: &str, value: &[u8]) -> Result<()>;
    fn delete(&self, key: &str) -> Result<()>;
}
```

| 平台 | 实现 |
|---|---|
| Windows | Credential Manager（`keyring` crate 或 Win32 直调） |
| macOS | Keychain（`security-framework`） |
| Android | Keystore 包装的 AES-GCM 密钥 + SharedPreferences 密文（JNI shim） |
| iOS | Keychain（`security-framework`） |

存放内容：设备密钥、本地库密钥（Free 用户的随机库密钥）、可选的 MK 缓存（开启"记住我"时）。

## 5. 桌面端（Iced 0.14）

### 5.1 窗口结构

```
┌────────────────────────────────────────────────────────────────────┐
│ 标题栏（自绘，Fluent 风格）  ─  □  ✕                    [同步状态]  │
├──────────────┬─────────────────────────────────────────────────────┤
│ 连接侧栏      │ 标签栏  [prod-1 ×][prod-2 ×][+]          [分屏][SFTP]│
│ 搜索框        ├─────────────────────────────────────────────────────┤
│ ▾ 生产        │                                                     │
│   • web-01    │                  终端视图（canvas/shader）            │
│   • db-01     │                                                     │
│ ▾ 测试        │                                                     │
│   ...         │                                                     │
│ [+ 新建]      ├─────────────────────────────────────────────────────┤
│ 状态栏: 延迟 12ms │ 加密: aes256-ctr │ 24×80 │ UTF-8 │ 已同步 3s 前 │
└──────────────┴─────────────────────────────────────────────────────┘
```

- 侧栏可折叠；支持拖拽调整宽度。
- 命令面板（`Ctrl+Shift+P`）覆盖：新建连接、切换主题、打开设置、同步。
- 主题：`iced-fluent-theme` 提供的组件 + 自有 token 覆盖层（见 `04-交互与UI规范.md`）。

### 5.2 Iced 集成要点

- 应用状态：`App { vm: ViewModel, core: CoreHandle, ... }`，`Message` 仅做转发与局部 UI 状态。
- 订阅：`Subscription::run_with(evt_rx, ...)` 将核心事件转为 `Message`。
- 终端控件：自定义 `Widget`/`canvas` 或 `shader` widget；需要处理键盘、鼠标、IME、滚轮、焦点。
- IME：Iced 0.14 的 `window::Event::Ime` 已接入，需在终端控件中正确转发 `Ime::Commit` 与 `Preedit`。
- 性能：终端视图只在 `RenderDelta` 非空时请求重绘，避免空闲时 60fps 空转。

### 5.3 打包

| 平台 | 产物 | 签名 |
|---|---|---|
| Windows | `.msi`（WiX）+ 可选便携 zip | Authenticode 代码签名 |
| macOS | Universal `.dmg` + `.app`（zip 供更新器） | Developer ID + 公证（notarization） |
| 自动更新 | 自研更新器：检查 manifest（Ed25519 签名）→ 下载 → 校验 SHA256 → 安装 | 更新清单必须签名 |

## 6. 移动端（Slint 1.18）

### 6.1 导航结构

```
[连接列表] ─┬─► [终端页] ─┬─► [文件页]
            │             └─► [转发页]
            ├─► [设置]
            └─► [账号/同步]
底部 Tab: 连接 / 最近 / 设置
```

- 移动端不做分屏、不做本地 Shell、不做 SSH Agent。
- 终端页：顶部连接名 + 状态，中间终端，底部键盘工具条（Esc/Tab/Ctrl/Alt/方向键/粘贴/放大）。
- 终端页支持横向滚动（宽于屏宽时）与双指缩放字号。

### 6.2 关键技术点

| 问题 | 方案 |
|---|---|
| 终端渲染 | `reedshell-term` 生成快照 → CPU 合成 RGBA → `slint::Image::from_rgba8(SharedPixelBuffer)`；只在新输出时刷新 |
| 键盘与 Ctrl/Alt | Slint `FocusScope` + `key-pressed`；工具条发送控制序列 |
| 中文输入法 | 通过平台桥接使用原生输入框（Android `EditText` / iOS `UITextField`），避免 Slint 内置输入框的 IME 兼容问题；提交文本写入终端 |
| 软键盘遮挡 | 监听 insets，动态调整可视区高度 |
| 后台连接 | Android：前台服务 + 常驻通知；iOS：后台仅限系统允许的短时任务，**App 进入后台超过系统时限后连接会断开**，需在文档与 UI 明示 |
| 安全存储 | Keystore / Keychain（`reedshell-secrets`） |
| 网络切换 | 监听连通性变化，触发重连与同步补推 |
| 触控选择 | 长按选词、手柄拖动选择、复制到系统剪贴板 |

## 7. 服务端（Axum）

### 7.1 模块

```
reedshell-server/src
├─ main.rs              启动、优雅关闭
├─ config.rs            env / toml 配置
├─ state.rs             AppState：DbPool、Redis、Keys、Config
├─ error.rs             统一错误 → Problem+JSON
├─ routes/
│  ├─ auth.rs           注册、登录、刷新、登出、找回密码
│  ├─ devices.rs        设备注册、列表、重命名、吊销
│  ├─ sync.rs           changes / push / state / stream
│  ├─ billing.rs        plans / checkout / webhook / redeem / entitlement
│  ├─ web.rs            浏览器会话相关（cookie 认证）
│  ├─ admin.rs          管理员 API
│  └─ health.rs         /healthz /readyz /metrics
├─ services/
│  ├─ auth_service.rs
│  ├─ sync_service.rs   序号分配、冲突判定、配额
│  ├─ billing_service.rs
│  ├─ entitlement.rs    Ed25519 签发
│  └─ mail_service.rs   SMTP（验证、找回密码）
├─ db/
│  ├─ models.rs
│  └─ repos/*.rs
├─ middleware/
│  ├─ auth.rs           Bearer / Cookie 双模式
│  ├─ ratelimit.rs      Redis 令牌桶
│  ├─ audit.rs          管理员写操作留痕
│  └─ request_id.rs
└─ jobs/
   ├─ cleanup.rs        tombstone 清理、过期令牌清理
   └─ renewals.rs       订阅到期提醒/降级
```

### 7.2 关键约束

- 所有 `/v1/sync/*` 请求必须同时校验：Access Token 有效、`device_id` 存在且未吊销、用户套餐具备同步权限。
- 同步写入必须在单个 MySQL 事务内完成：分配序号 → 版本乐观锁 → 写入密文 → 更新 `change_seq`。
- 服务端**不实现**任何解密函数；代码评审时禁止在 server 中引入 `reedshell-crypto` 的解密 API（只允许签名/随机数工具）。
- 管理员 API 与用户 API 使用独立路由前缀、独立鉴权中间件、独立 Cookie。

### 7.3 部署拓扑

```
Internet ──► Caddy (TLS, HSTS) ──► reedshell-server :8080
                                   ├─► MySQL 8.4（主库，日备 + binlog）
                                   └─► Redis 7（限流/缓存，可丢数据）
```

- 单机 Docker Compose 起步；纵向扩容优先，后续可拆库。
- 健康检查：`/healthz`（进程）、`/readyz`（DB/Redis 可用）。
- 备份：每日全量 + binlog 增量，保留 14 天；恢复演练每季度一次。

### 8.2 前端结构

```

├─ features/

```

- 状态：服务端状态用 TanStack Query；表单用 react-hook-form + zod；不引入全局状态库。
- 认证：用户端用 `HttpOnly + Secure + SameSite=Lax` 会话 Cookie；写操作带 CSRF token。
- 安全：严格 CSP、`Referrer-Policy: no-referrer`、禁止内联脚本（除 Vite 生产哈希）。
- 浏览器端只做 `auth_key` 派生与可选的密码重包裹，**永不下载 MK 的明文**到 Web 页面以外的场景。

## 9. 关键流程

### 9.1 首次注册（客户端或 Web）

```
用户输入邮箱+密码
   │
   ├─ HKDF(Argon2id(password, salt_auth), "auth")  → auth_key      ──► 上传服务端（服务端再哈希存储）
   ├─ HKDF(Argon2id(password, salt_enc ), "enc" )  → KEK           （不上传）
   ├─ 随机生成 MK(32B)
   ├─ wrap(MK, KEK)                                 → wrapped_mk    ──► 上传
   └─ 生成恢复码 → wrap(MK, recovery_key)           → wrapped_mk_rc ──► 上传
```

### 9.2 登录并解锁

```
客户端 ──GET /v1/auth/params?email──► 服务端返回 salt_auth / salt_enc / kdf 参数
客户端计算 auth_key ──POST /v1/auth/login──► 服务端校验哈希，发 Access(15m)+Refresh(30d)
客户端取 wrapped_mk → KEK 解包 → MK 驻留内存（zeroize on drop）
```

### 9.3 同步

```
本地写入 → items.dirty=1 + outbox
        → Push(base_version, ciphertext) ──► 服务端事务校验版本、分配 seq
        → Pull(since=cursor) ──► 解密 → 按 HLC 合并 → 更新本地 → cursor 前进
（详见 03-安全与同步协议.md）
```

### 9.4 SSH 连接（带跳板）

```
UI 选中连接 → 构建 Target + Hops
  hop1 connect → auth1 → direct-tcpip(hop2:22)
    hop2 connect → auth2 → direct-tcpip(target:22)
      target connect → auth → open shell channel(pty, size)
        → 转发 channel 数据到 reedshell-term
        → 并行打开 sftp 通道（按需）
```

### 9.5 SFTP 上传（断点续传）

```
选择本地文件 → stat 远程文件
  存在且 remote.size < local.size → open(append) 从 remote.size 续传
  否则 → open(write, truncate)
分块 256KB → 写 → 更新进度 → 完成后 setstat(size, mtime) 校验
失败 → 重试 3 次（指数退避）→ 进入失败队列可手动重试
```

## 10. 错误模型与日志

### 10.1 错误

- 库层：`thiserror` 定义结构化错误（`SshError`、`StoreError`、`SyncError`、`CryptoError`）。
- 应用层：转换为 `UserFacingError { code: &'static str, detail: String, hint: Option<Localized> }`。
- 错误码规则：`E-<模块 3 位>-<序号>`，例如 `E-SSH-001` 连接超时、`E-SYN-002` 设备已吊销。
- 网络错误文案必须包含：发生了什么、可能原因、可执行动作（重试/检查代理/查看日志）。

### 10.2 日志

| 端 | 方案 |
|---|---|
| 客户端 | `tracing` + 滚动文件（默认 10MB × 5），级别可配置；默认不记录终端内容与凭据 |
| 服务端 | `tracing` JSON → stdout，由容器收集；请求 ID 贯穿 |
| Web | 前端错误上报（可选 Sentry），不含 token |

**禁止记录**：密码、私钥、口令、MK/KEK、终端输出、剪贴板内容、Authorization 头。
