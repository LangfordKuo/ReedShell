### 1.1 依赖关系

```
M0 ──► M1 ──► M3 ──► M4 ──► M7
        │       ▲
        └► M2 ──┘
                 └──► M5 ──► M6
```

### 1.2 M1 任务拆分

1. 工程骨架：workspace、CI、lint、Docker Compose、迁移框架。
2. 数据库迁移与仓储层。
3. 认证：注册、登录、刷新、邮箱验证、找回、改密、恢复码。
4. 设备：注册、列表、重命名、吊销、签名校验。
5. 同步：push/changes/snapshot/state、序号分配、冲突返回、配额。
6. 计费：套餐（¥6/月、¥60/年）、易支付 V1 下单与异步通知、兑换码、授权 JWT、到期与对账任务。
7. Web：公开页、认证页、概览、设备、订阅、账号。
8. 管理后台：管理员登录 + TOTP、用户、订单、兑换码、统计、审计。
9. 安全：限流、CSP、CSRF、审计、依赖审计。
10. 测试：API 集成测试、Playwright 关键路径。

### 1.3 M2 任务拆分

1. `reedshell-crypto`：KDF、AEAD、包裹、恢复码、测试向量。
2. `reedshell-store`：SQLite schema、迁移、密文仓储、钥匙串抽象。
3. `reedshell-sync`：HTTP 客户端、outbox、cursor、冲突、授权校验、退避。
4. `reedshell-core`：ID、领域模型、错误、HLC。
5. CLI 工具 `xtask sync-sim`：模拟多设备并发与断线，输出收敛报告。
6. 属性测试与故障注入。

### 1.4 M3 任务拆分

1. Iced 框架：窗口、路由、主题、`CoreHandle` 桥接。

4. `russh` 集成：认证、PTY、resize、断线重连。
5. 会话/标签状态机与快捷键。
6. 登录、同步状态、冲突提示。
7. 已知主机校验流程。
8. 日志、崩溃捕获、诊断包导出。

### 1.5 M4 任务拆分

1. SFTP：通道、浏览、队列、续传、在线编辑。
2. 端口转发：本地/远程/动态、规则管理、状态。
3. 跳板机：多跳建链、逐跳认证、错误定位。
4. 设置：外观/终端/快捷键/网络/同步。
5. 终端增强：搜索、链接、块选、主题导入。
6. 自动更新与打包签名（Win/macOS）。
7. 性能与内存专项。

## 2. 工程规范

### 2.1 语言与工具链

- Rust stable，`rust-toolchain.toml` 固定版本，每季度评估升级。
- Edition 2024（若依赖兼容；否则 2021）。
- 格式化：`cargo fmt`，CI 校验。
- Lint：`cargo clippy --all-targets -- -D warnings`；非测试代码禁止 `unwrap()`/`expect()`（白名单需注释）。
- 依赖：`cargo-deny`（许可证、重复版本、安全公告）、`cargo-audit`。
- 前端：`eslint` + `prettier` + `tsc --noEmit`；禁止 `any`（除非注释说明）。

### 2.2 分支与提交

- 主干开发：`main` 始终可发布；功能分支 `feat/<scope>`，生命周期 ≤ 3 天。
- 提交：Conventional Commits（`feat:`, `fix:`, `refactor:`, `docs:`, `test:`, `chore:`）。
- PR 必须：CI 全绿、至少 1 人 review、附变更说明与测试证据。
- 禁止直接推 `main`；发布打 `vX.Y.Z` tag。

### 2.3 版本号

- 产品版本：SemVer；`0.x` 为开发期，GA 为 `1.0.0`。
- 协议版本：URL `/v1/`，数据库 `schema_version`，密文 `schema` 字段，三者在文档中同步记录。
- 客户端与协议兼容矩阵在 `docs/compatibility.md` 维护（M1 建立）。

### 2.4 代码组织约定

- 一个 crate 一个职责，禁止循环依赖（CI 用 `cargo-depgraph` 检查）。
- 公共 API 必须有文档注释与示例。
- 领域错误用枚举，禁止字符串错误跨层传递。
- 所有用户可见文案走 i18n，禁止硬编码。
- 所有网络请求有超时、重试上限、取消机制。
- 所有后台任务可被优雅关闭（`CancellationToken`）。

### 2.5 配置

- 服务端：环境变量 + `config.toml`，启动时校验并输出脱敏配置摘要。
- 客户端：设置存本地（加密），编译期常量只放默认值。
- 密钥：仅环境变量/secret 文件；仓库内提供 `.env.example`。

## 3. 测试策略

### 3.1 金字塔

| 层 | 覆盖 | 工具 |
|---|---|---|
| 单元 | 密码学向量、HLC、AAD 编码、路径处理、解析器 | `cargo test`、`proptest` |
| 集成 | 同步协议、认证、计费、权限 | `sqlx` + 测试 MySQL/Redis（Docker）、`wiremock` |
| 端到端（Web） | 注册→付费→设备→管理员 | Playwright |
| 端到端（桌面） | 连接真实 SSH、SFTP、转发 | 脚本化 SSH 容器 + 手工清单 |
| 终端兼容 | vttest、fixture 回放 | 黄金文件比对 |
| 移动 | 核心复用测试 + 真机清单 | `cargo test` + 手工 |

### 3.2 测试环境

- SSH 测试床：Docker 启动 `openssh-server`（密码、密钥、跳板多实例）。
- 服务端测试：独立数据库 `reedshell_test`，每个测试事务回滚。
- 同步模拟：`xtask sync-sim` 生成 N 台虚拟设备，随机操作 + 随机断线，断言最终一致。

### 3.3 质量门禁

- 行覆盖率：核心库 ≥ 80%，服务端 ≥ 70%，UI 不设硬指标但关键流程必须有测试。
- 每个 P0 缺陷必须有回归测试。
- 发布前手工回归清单（见 `docs/qa-checklist.md`，M3 建立）。

## 4. CI/CD

### 4.1 CI 流水线

```
push/PR:
  fmt → clippy → test (linux) → test (windows, macos)
      → web lint/build/test
      → cargo-deny / cargo-audit / npm audit
      → server docker build + migrations check
      → android cross-compile (cargo-ndk)
      → ios cross-compile (macOS runner)
```

- 缓存：`sccache`、cargo registry、pnpm store。
- 构建时间目标：PR < 15 分钟。
- 失败即阻断合并。

### 4.2 发布流水线

| 平台 | 触发 | 步骤 |
|---|---|---|
| 服务端 | tag `server-v*` | 构建镜像 → 推送 → 迁移预检 → 滚动发布 → 健康检查 |
| Windows | tag `v*` | 构建 → 签名（Authenticode）→ 生成 `latest.json`（Ed25519 签名）→ 上传 |
| macOS | tag `v*` | Universal 构建 → 公证 → 装订（staple）→ 生成更新清单 |
| Android | tag `v*` | AAB 构建 → 签名 → 上传 Play Console / 分发站 |
| iOS | tag `v*` | Archive → TestFlight → 审核 |
| Web | `main` 合并 | 构建 → 上传静态资源 → 原子切换 |

### 4.3 回滚

- 服务端：保留上一版本镜像，数据库迁移必须**向后兼容一个版本**（先加列/表，后删）。
- 客户端：更新器支持"下载并安装指定版本"；严重问题时从清单撤下版本。
- Web：静态资源带 content hash，秒级回滚。

## 7. 完成定义（Definition of Done）

一个功能算完成，必须同时满足：

- [ ] 代码合并到 `main`，CI 全绿
- [ ] 有单元/集成测试，关键路径有端到端测试
- [ ] 用户可见文案已国际化（中/英）
- [ ] 错误路径有明确提示与恢复动作
- [ ] 不记录敏感信息到日志
- [ ] 桌面端 60fps / 移动端 30fps 无回归
- [ ] 文档更新（用户手册或内部注释）
- [ ] 通过安全评审（涉及认证、加密、网络边界时）
- [ ] 在 Windows/macOS（及对应移动平台）真机验证
